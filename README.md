# ZIDDU

ZIDDU is a hyperlocal social-commerce app for discovering neighborhood shops, posts, reels and offers.

## Stack

- Next.js App Router and TypeScript
- Tailwind CSS 4
- Better Auth with simulated development OTP
- Prisma ORM 6.19 with MySQL

The app keeps UI, route handlers, services, authentication and database utilities in the Next.js project. Database access is server-side through Prisma Client and `DATABASE_URL`.

## Run locally

1. Set `DATABASE_URL` in `.env` to the MySQL URL from `.env.example` and set a random `BETTER_AUTH_SECRET`. Prisma CLI reads `.env`, which Next.js also loads.
2. Download the Aiven CA certificate to `prisma/ca.pem`. The example URL enables strict TLS certificate verification; do not commit the certificate or database credentials.
3. Install dependencies with `npm install` and generate the Prisma client with `npm run db:generate`.
4. Apply the MySQL schema with `npm run db:push`.
5. Start the app with `npm run dev` and open `http://localhost:3000`.

Sign in at `/login` with an Indian mobile number or configured Google OAuth. For Google, set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` and register `BETTER_AUTH_URL/api/auth/callback/google` as an authorized redirect URI. In development, the six-digit OTP is printed only in the Next.js server terminal as `[ZIDDU DEV OTP] +91XXXXXXXXXX -> XXXXXX`; it is never included in the API response. OTP digests are stored in the Prisma `PhoneOtp` table, expire after five minutes, are single-use, allow five attempts and enforce a 60-second resend cooldown. A real SMS delivery adapter must replace the development callback before production use.

## Project layout

- `app/`: App Router pages, global styling and API route handlers
- `components/features/`: interactive product features
- `lib/auth.ts`: Better Auth configuration and OTP plugin
- `lib/auth/`: phone normalization, OTP storage/verification and browser auth client
- `lib/auth/session.ts`: reusable server-side session lookup/require helper
- `components/features/auth/`: phone login and session/logout controls
- `lib/db/`: Prisma Client singleton
- `lib/validation/`: shared Zod schemas for Indian user, location, shop, post, offer, product and interaction inputs
- `lib/server/`: shared API error response mapping
- `prisma/schema.prisma`: MySQL relational models for auth, users, shops, locations, posts, offers, products, follows, likes, saves, purchases and affiliates
- `services/`: server-side product data and business logic
- `types/`: shared TypeScript contracts

The current routes are `/` for discovery, `/login` for phone OTP authentication, `/onboarding` as a Phase 3 placeholder, and `/api/auth/[...all]` for Better Auth. The discovery content and simulated purchase history remain demo data. IDs are strings generated as CUIDs unless explicitly assigned by seed data. Existing `Shop` is the vendor/business record and references a separate `Location`, avoiding a duplicate Vendor model. Restaurant menu categories/subcategories and the existing `Product` catalog represent the diagram's menu tables/items. `Post` references its `Shop` and can reference a unique `Offer`; offer targets use a typed target ID because they may refer to different catalog models. `Bill` covers vendor-to-end-user bills; `Purchase` remains the existing purchase-history record. Categories are restricted to Restaurant, Furniture and Electronics; prices are stored as INR amounts. Posts have only Image or Video types and no comment model or field. Simulated checkout does not charge a payment method.

This switches the application schema and client from MongoDB to MySQL; it does not copy existing MongoDB records. `npm run db:push` creates or updates the MySQL schema, and `npm run db:generate` regenerates Prisma Client. If existing MongoDB data must be retained, export and migrate those records separately before directing production traffic to MySQL.

## Affiliate program

An affiliate is an optional profile on the existing end-user account; it does not create another User or login. The hub is available at `/affiliate`, with referrals, earnings, withdrawal tracking and affiliate profile sections under the same route. Commission rules, the 30-day attribution window and minimum withdrawal live in `lib/affiliate/config.ts`. Referral codes are signed into an HttpOnly cookie, while referral conversion and order commissions are resolved server-side against existing Users, Shops and Bills.

Payout destinations store only simulated display details (including the last four digits); do not enter real bank account numbers. Withdrawal requests remain pending records and no funds are transferred. This repository has no vendor registration route yet, so vendor clicks are tracked and the trusted vendor-conversion service is ready for a future registration handler, but vendor conversions are not generated by the current app.

Affiliate idempotency and relation indexes, including uniqueness for nullable `Post.offerId`, are declared in `prisma/schema.prisma` and created by `npm run db:push`.
